Hackthebox: MakeSense

Foued SAIDI Lv5
  2026-11-02 18:42:19 2026-11-02 18:42:19 Created   2026-11-02 20:54:36 2026-11-02 20:54:36 Updated

Overview

MakeSense is a medium-difficulty machine from Hack The Box that is all about reading the application instead of fighting it. We start with a WordPress agency site running a custom webagency theme whose home-grown contact form stores our message and renders it back to an administrator unsanitised, giving us a stored XSS with an admin reader — which we use to mint ourselves a brand new administrator account. The theme editor is locked down with DISALLOW_FILE_EDIT, but plugin upload is not, so we ship a one-file plugin webshell and land code execution as www-data. From there, wp-config.php hands us the database password, which is reused for SSH as walter and gives us the user flag. Privilege escalation is the genuinely fun part: an internal OCR web app listening on 127.0.0.1:8001 runs as root and lets us save whatever text Tesseract reads out of an image to any filename we want. We render a PHP webshell as a PNG, let the OCR engine read it back, save the recognized text as shell.php, and the root-owned PHP server executes our own handwriting.

Foothold — Stored XSS in the Contact Form

The question we always ask about a contact form is: does an admin read these messages in wp-admin, and is the message rendered raw? On this box, it is. The message field is stored and shown back to the administrator verbatim, which makes this a stored XSS with an admin viewer — meaning we can run JavaScript as the administrator.

The highest-value thing to do with that primitive is to mint ourselves a new administrator account. Our payload fetches /wp-admin/user-new.php (same origin, so the admin’s cookies ride along), scrapes the _wpnonce_create-user token out of the HTML, and POSTs a new user with the administrator role:

Privilege Escalation — The OCR App That Types Out Our Shell

Looking at what’s listening locally as walter, something is bound to loopback only:

That’s the “MakeSense” recognizer — a canvas web app where you sketch some text, it OCRs it with Tesseract, and then lets you save the recognized text to a filename of your choice. It sits behind HTTP Basic auth, and walter‘s password works there too. Critically, it runs as root:

So it’s PHP’s built-in development server, rooted at /root/ocr4/, running as root — and the “save” feature writes into /root/ocr4/saved/. There is no extension check and no content filter on the filename we supply. If we save the recognized text as shell.php, the root-owned PHP server will happily execute it the next time we request it. The recognizer is our arbitrary file-write primitive; all we have to do is feed it the right text.

Rendering a Webshell Tesseract Can Read

The catch is that the input is an image, so Tesseract has to read our PHP back exactly — one mangled quote or bracket and the saved file is broken PHP. Root Flag

All that’s left is to request the file we just drew, and watch PHP run it as root:

And that’s root. If you’d rather drive the whole thing from your own box instead of from the shell, just forward the port first — ssh -L 8001:127.0.0.1:8001 walter@makesense.htb — and run the exact same curls against localhost:8001.

Kill Chain

Takeaways

  • A contact form is an injection sink with an admin reader. Storing user input and rendering it into the wp-admin panel raw turns “leave us a message” into “run code in an administrator’s browser.” Escape on output, always.
  • DISALLOW_FILE_EDIT is only half a control. It stopped the theme editor but not plugin upload — and a WordPress administrator is effectively RCE unless you also lock down plugin and theme installation with DISALLOW_FILE_MODS.
  • DB password = SSH password. wp-config.php is the first thing worth reading the moment you’re www-data, and reusing that password for a shell account is the entire user step on this box.
  • The OCR app is the textbook “trusted output written to an executable location” bug. It runs as root, applies no extension or content check on the save filename, and serves its own docroot with php -S — so an attacker-controlled image becomes an attacker-controlled root-executed file. The exploit isn’t in Tesseract at all; it’s in trusting whatever Tesseract reads and letting the caller name the output .php.

That was it for MakeSense, hope you learned something new!
